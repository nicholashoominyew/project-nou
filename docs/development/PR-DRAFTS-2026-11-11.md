- **`NOU_PROFILE_DIR`:** lets the app run against a disposable profile folder. Unset behaviour is unchanged.

## PR 5 — `feature/approval-gateway` → `feature/home-page`

**Title:** Add the approval gateway: tokens, proposals, audit log, approval screen and an opt-in local API (schema v6)

### What
- **Rule:** AI tools and bots can only *ask*. A person approves each request on the Home page, and the app applies the change itself through its normal commands. Nothing a client sends can change a note directly. Design and threat model: `docs/architecture/ADR-004-approval-gateway.md`.
- **Schema v6** (`db/notes/006_gateway.sql`): `api_tokens` (SHA-256 hashes only), `proposals`, and an `audit_log` whose triggers refuse UPDATE and DELETE.
- **Core** (`gateway.rs`): scoped, revocable tokens (secret shown once); proposals with scope and operation checks, payload limits, duplicate protection and a 50-pending cap; decide once; apply only after approval; 7-day expiry; every step audited. Revoking a token cancels its waiting requests.
- **Local API** (`gateway_http.rs`, new dependency `tiny_http`): **off until the owner turns it on**, loopback `127.0.0.1` only. Refuses browser requests (`Origin`), foreign `Host` headers (DNS rebinding), bodies over 70 KB, more than 120 requests a minute, and missing or revoked tokens. Reads need a scope; the only write is `POST /v1/proposals`, which queues a request. Read responses are marked `content_is_untrusted_data`.
- **Approvals widget on Home** and an **AI access** screen (create/revoke tokens, API switch, activity). The widget shows the exact operation and fields, labels the client's own description as unverified, and renders all text as plain text. Appliers exist for `create_page`, `rename_page`, `set_value` and `create_row`; other kinds can only be rejected.
- **Also in this PR:** a fix for layout jitter while typing (`4c81696`). The tag row and the Linked-from panel (from PR 3) reacted to the save status on every keystroke and shifted the editor. They are now kept out of the save cycle, with a regression test that fails on the old behaviour.
- Docs: `docs/development/GATEWAY.md`.

### Risk and compatibility
- **One-way schema step (v6).** Same rollback snapshot and rehearse-on-a-copy advice as PRs 2 and 3.
- **New dependency** `tiny_http` (and its small dependency tree) changes `Cargo.lock`; the CI uses `--locked`, so the lockfile is part of this PR.
- **New network surface**, but only when switched on, only on loopback, only with a token. Review `gateway_http.rs` first.
- Tokens are shown once and never stored; a lost token must be replaced.

### Verified
TypeScript clean; 135 Vitest, 61 Rust library, 11 native-core and 16 Python SQL tests pass on this branch's head. Covered by tests: token hashing and one-time secrets, scopes, duplicate protection, decide-once, revocation, expiry, append-only audit log, request handling (browser/host refusal, size, auth), and a real-socket round trip that also stops the listener. In the real app binary on a disposable profile: the schema 1→6 migration chain ran and the integrity check was `ok`.

**Not verified:** the Home approvals widget, the token screen and a live API call in the real window; use with any real AI tool; Windows Firewall behaviour when the listener starts.

### Known limitations
No MCP transport yet (tools using MCP over stdio need a small bridge). `append_text` and `add_checklist_item` cannot be applied yet. A page read returns searchable plain text only. One global rate limit, not per token. The local web clipper and scheduled-job runner are not built.
